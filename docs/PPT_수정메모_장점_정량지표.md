## 2. 타이머의 장점 정리

### ① 대원 안전 (핵심)
- **경고음을 한 사람 더 듣습니다**: 대원 공기호흡기 경보는 대원 혼자 듣지만, 이 앱은 지휘부가 한 번 더 듣습니다 → "이중 안전장치"
- **소음 속에서도 알아챕니다**: 소리·진동·음성("위험. 1착 작전 펌프차, 40분 경과")·화면 깜빡임
- **위험한 대를 놓치지 않습니다**: 경고·위험인 대는 항상 맨 위로 가고, 위험이면 1분마다 음성 반복
- **경보를 꺼도 위험 단계에서 다시 알립니다**: 경보 정지는 소리만 끄고 색은 그대로 두며, 위험이 되면 다시 울림

### ② 지휘 효율
- **기억·메모 대신 앱이 시간을 잽니다**: 여러 층·방면에 동시에 진입해도 대마다 따로 측정
- **현황 보고가 버튼 한 번입니다**: 층별로 어느 대가 몇 분째인지 정리하고 보고 문장까지 자동으로 만듦 *(새로 추가)*
- **상황판 숫자로 바로 판단합니다**: 대기·진입중·경고·위험 대 수를 크게 표시
- **층을 옮기거나 2인1조로 나눠도 시간이 이어집니다**
- **진입 전에 빠진 것을 막습니다**: 위치나 대원이 비어 있으면 진입 시작이 안 됨 → 누가 어디 들어갔는지 모르는 상황을 막음 *(새로 추가)*

### ③ 준비 부담이 거의 없습니다 *(새로 추가)*
- **지금 쓰는 출동대편성표를 그대로 올립니다**: 엑셀·한글·PDF 모두 읽음, 따로 입력할 필요 없음
- **응원 출동에도 씁니다**: 여러 소방서 편성표를 함께 담음
- **지휘관이 누르는 건 사실상 버튼 하나입니다**: 무전을 받으면 '진입 시작' 한 번

### ④ 기록과 사후 관리 *(기능을 효과로 바꿔 쓰기)*
- **사후 검토(디브리핑) 근거가 남습니다**: 진입·이동·경보·조 나누기를 시각·대원·위치와 함께 자동 기록
- **엑셀로 내려받아 보고서·교육 자료로 씁니다**
- **안전사고가 나면 활동시간을 객관적으로 확인할 수 있습니다**

### ⑤ 도입이 쉽고 보안에 유리합니다 *(예상질문·부록용)*
- **설치 없이 비용이 들지 않습니다**: 휴대폰·태블릿 브라우저에서 주소(QR)만 열면 됨
- **인터넷이 끊겨도 동작합니다**: 한 번 열어 두면 오프라인에서도 씀
- **개인정보가 서버로 나가지 않습니다**: 대원 이름 같은 데이터는 그 기기에만 저장되고, 한 번에 지울 수도 있음
- **현장 중에 화면이 꺼지지 않습니다**

### ⚠️ 표현할 때 주의
- 이 앱은 압력을 직접 재지 않고 **진입한 뒤 지난 시간**으로 판단합니다.
- "공기 잔량을 알려준다"는 쓰지 말고 → **"활동시간 기반 교대 판단 지원"**으로 표현합니다.

## 3. 정량 지표

> 원칙: 심사위원은 "그 수치는 어떻게 나왔나요?"를 꼭 묻습니다. **지어낸 수치는 쓰지 말 것.**
> A(앱 기능에서 나오는 사실)와 B(모의훈련에서 직접 잰 값)만 씁니다.

### A. 측정 없이 바로 쓸 수 있는 수치 (앱 기능에서 나오는 사실)

| 항목 | 기존 | 도입 후 |
|---|---|---|
| 대원 정보 입력 | 차량당 대원 4~5명 이름 수기 입력 | **0건** (편성표 자동 인식) |
| 진입 등록 | 시각 확인 → 메모 → 경과 시간 암산 | **버튼 1회** |
| 경보를 듣는 사람 | 1명 (진입 대원 본인) | **2명** (대원 + 지휘부) |
| 경보 수단 | 1가지 (경고음) | **4가지** (소리·진동·음성·화면) |
| 동시에 관리하는 대 수 | 지휘관 기억력에 의존 | **제한 없음**, 대마다 자동 측정 |
| 활동 기록 정리 | 상황 종료 뒤 수기 작성 | **0분** (자동 기록, 엑셀 내려받기) |
| 도입 비용·설치 | — | **0원 / 설치 없음** (QR로 접속) |

### B. 시간 단축 수치 ("1시간 → 10분" 같은 것): 모의훈련으로 측정

**방법**
- 센터 동료 3~5명과 30분 정도 도상훈련
- 가상 화재 시나리오: 예) 5개 대가 3개 층에 진입
- 같은 시나리오를 **① 기존 방식(종이·화이트보드·기억)**과 **② 앱**으로 각각 진행하고 스톱워치로 측정

| 측정 지표 | 재는 방법 | 예상되는 차이 |
|---|---|---|
| **현황 보고 시간** | "현재 진입 현황 보고하라" 지시부터 보고 끝까지 | 앱은 버튼 한 번으로 몇 초 안에 끝남 → **가장 극적인 수치가 나올 항목** |
| 특정 대 경과 시간 확인 | "작전 펌프차 몇 분째야?" 질문에 답할 때까지 | 앱은 바로 보임 |
| 교대 대상 파악 | "30분 넘은 대 전부 말해" 지시에 답할 때까지 | 앱은 맨 위에 정렬되어 있음 |
| 교대 시점 누락 | 시나리오 중 30분이 넘은 대를 놓친 횟수 | 기존 n건 → 앱 0건 |
| 사후 기록 작성 | 훈련 뒤 활동 기록 문서를 완성하기까지 | 수기 n분 → 앱 0분 |

**발표 문구 예시** (괄호 안 숫자는 실제로 잰 값으로 바꿔 넣기)
> "5개 대·3개 층 모의훈련 결과, 현황 보고 시간 **(3분 20초) → (15초) ((94)% 단축)**, 교대 시점 누락 **(2)건 → 0건**"

**출처 표기**: 슬라이드 아래에 `계양소방서 작전센터 모의훈련(2026.11, 대원 n명)` 적기 → 신뢰도가 크게 오름

### C. 배경 통계 (문제 제기 슬라이드용)
- 소방청 통계연보: **화재진압 중 공상자 수**, **호흡기·탈진 관련 사고 비율**
- 3번 슬라이드(10bar 사례) 옆에 두면 개인 경험이 구조적 문제로 확장됨
- ※ 정확한 수치는 원문에서 직접 확인한 뒤 출처와 함께 쓰기
